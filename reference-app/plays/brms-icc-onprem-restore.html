BRMS + ICC backup to COS, restore back on-prem

Same save path as the cloud-DR play. Full-system recovery still cannot IPL from Cloud Object Storage. A running on-prem helper pulls QCLDBIPL volumes, then a staging LPAR network-installs from NFS (or you burn those volumes to optical). PowerVS and Transit Gateway are not on this path.

Is the NFS + staging model right?

Yes for a full-system restore. IBM i cannot D-mode IPL from COS. A running helper must land the QCLDBIPL optical first, then the staging LPAR installs from NFS or DVD. After BRMS, TCP, and ICC are back, the staging LPAR pulls the rest from COS over the same VPN + VPE path.

  1. Keep the helper on-prem. Do not NFS-install across the VPN from PowerVS. D-mode over IPsec is slow and fragile.
  2. Chicken and egg. If production is dead, you still need a second running IBM i (or a PC that downloads QCLDBIPL and burns optical). The staging LPAR cannot pull from COS until ICC exists on it.
  3. These are BRMS virtual volumes in a COS bucket (QBRMS_<system>), not a FalconStor / physical VTL. Same ICC objects either way.
  4. Object-level restore is simpler. A still-running IBM i can CPYFRMCLD / RSTLIBBRM from COS with no NFS helper.
  5. No PowerVS, no TGW on this option. Cloud is only the object store.
